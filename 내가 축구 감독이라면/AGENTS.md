# RE:TACTIC 작업 지침

## 제품 관점

- 이 서비스는 일반 관리 대시보드가 아니라 `월드컵 중계 분석실 × 감독의 전술 보드` 경험이다.
- 화면의 판단 흐름은 항상 `관측 데이터 → 문제 진단 → 사용자 개입 → 기준 전술과 비교 → 이점·리스크` 순서를 지킨다.
- 실제 관측값, 사용자가 입력한 전술, 규칙 기반 시나리오 점수를 시각적·언어적으로 섞지 않는다. 점수를 실제 경기 결과 예측처럼 표현하지 않는다.
- 기존의 짙은 피치 그린, 라임 포인트, 각진 패널, 데이터 터미널 톤을 기본 시각 언어로 유지한다. 장식보다 경기 맥락과 의사결정 위계를 우선한다.

## 에이전트 스킬 라우팅

- 새 화면·컴포넌트를 설계하거나 시각 완성도를 높일 때 `.agents/skills/frontend-design/SKILL.md`를 사용한다.
- UI/UX·접근성 감사를 할 때 `.agents/skills/web-design-guidelines/SKILL.md`를 사용한다.
- React 구조나 렌더링 성능을 수정할 때 `.agents/skills/react-best-practices/SKILL.md`에서 해당 규칙만 읽는다.
- 외부 스킬의 일반론보다 이 문서의 RE:TACTIC 제품 제약을 우선한다.

## UI 구현 기준

- 한 화면에는 하나의 주 행동을 둔다. 보조 행동은 대비와 위치를 낮춘다.
- 현재 단계와 완료 단계는 색상뿐 아니라 모양·텍스트·`aria-current`로 구분한다.
- 긴 모바일 화면에서도 현재 모드, 진행 단계, 다음 행동을 잃지 않게 한다.
- 모든 핵심 조작은 포인터·터치·키보드로 가능해야 한다. 드래그 UI에는 방향키 대체 조작과 화면 낭독기 설명을 제공한다.
- 모바일 터치 대상은 최소 44px을 목표로 하고, 모든 인터랙티브 요소에 명확한 `:focus-visible` 상태를 둔다.
- 애니메이션은 `transform`과 `opacity`를 우선하며 `prefers-reduced-motion`을 존중한다. `transition: all`을 사용하지 않는다.
- 폼 컨트롤은 보이는 레이블, 안정적인 `name`, 적절한 `type`·`inputMode`·`autocomplete`을 갖춘다.
- 수치 비교에는 `font-variant-numeric: tabular-nums`를 적용한다. 긴 한국어 문구는 `word-break: keep-all`과 `overflow-wrap`을 함께 점검한다.
- 이미지에는 대체 텍스트와 고유 크기를 제공하고, 첫 화면 밖의 이미지는 지연 로드한다.

## 반응형·검증 기준

- 기준 뷰포트는 데스크톱 1440×900, 태블릿 900×1200, 모바일 390×844이다.
- 320px 이상에서 가로 스크롤이 생기지 않아야 한다.
- 변경 후 `npm run typecheck`, `npm run build`, `npm run test:e2e`를 실행한다.
- 레이아웃 변경은 홈, 브리핑, 전술판, 결과, 범용 스튜디오의 데스크톱·모바일 캡처를 확인한다.
- 자동 테스트만으로 확인하기 어려운 키보드 순서, 포커스 표시, 고정 CTA 가림, 한글 줄바꿈을 수동으로 점검한다.
