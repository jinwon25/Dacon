# RE:TACTIC 프론트엔드 디자인 플레이북

검토일: 2026-07-22

## 1. 목표

RE:TACTIC의 핵심 경험은 “데이터를 보는 것”이 아니라 “근거를 읽고 전술을 조작한 뒤 기존 기준과 비교해 결정을 내리는 것”이다. 디자인은 이 판단 순서를 짧고 확실하게 보여줘야 한다.

시각 방향은 **월드컵 중계 분석실 × 감독의 전술 보드**로 정의한다. 짙은 피치 그린과 라임 포인트, 수치가 정렬된 분석 패널, 실제 경기장의 공간감을 유지하되, 게임 UI처럼 결과를 확정적으로 과장하지 않는다.

## 3. 정보 위계

모든 실전 분석 화면은 다음 다섯 층을 유지한다.

1. **경기 맥락:** 팀, 점수, 시간, 반드시 달성해야 할 목표
2. **관측 근거:** 공식 보고서나 공개 이벤트 데이터에서 직접 읽을 수 있는 값
3. **문제 진단:** 근거를 감독의 언어로 요약한 한 문장
4. **조작:** 포메이션, 선수 위치·역할·교체, 팀 지시
5. **비교 결과:** 실제 기준 전술 대비 변화량, 이점, 리스크, 운용 조건

관측값은 흰색·중립색, 사용자 변경은 라임, 위험은 주황·빨강, 가정과 주의 문구는 낮은 대비의 보조 텍스트로 표현한다. 색상만으로 의미를 전달하지 않고 레이블과 기호를 함께 쓴다.

## 4. 디자인 토큰 원칙

- 배경: `#06100d` 중심의 저채도 다크 그린
- 핵심 행동: `--lime: #bafc4b`
- 긍정 보조: `--mint: #59e0a8`
- 위험: `--amber`, `--red`
- 패널: 불투명도 있는 짙은 녹색과 1px 경계선
- 모서리: 작은 반경을 사용해 분석 장비의 각진 인상을 유지
- 타이포그래피: 한국어 본문 가독성을 먼저 확보하고, 큰 제목은 짧고 강하게, 수치는 tabular 숫자로 정렬
- 모션: 상태 변화 이해에 필요한 이동만 160–250ms, 장면 재생은 의미 있는 시간축 표현에 한해 사용

## 5. 화면별 체크

### 홈

- 첫 5초 안에 `실제 데이터`, `직접 전술 조작`, `비교 결과`를 이해할 수 있어야 한다.
- 주요 행동은 `실제 경기에서 시작`, 보조 행동은 `빈 전술판 열기`로 유지한다.

### 브리핑

- 카드 수보다 읽기 순서가 중요하다. `관측 구간 → 필요한 결과 → 우선 검토` 스트립과 한 문장 결론을 먼저 보이게 한다.
- 모바일에서는 긴 근거를 읽는 동안 현재 단계와 `전술 보드로 이동` 행동을 잃지 않게 한다.
- 분석 번호는 장식으로 쓰지 않는다. `DATA`, `READ`, `ACT`, `SPACE`, `PASS`, `FLOW`처럼 내용의 역할을 표시한다.

### 패스 네트워크

- 데스크톱은 양 팀을 같은 축척의 작은 경기장으로 동시에 비교하고 모바일만 팀 전환 버튼을 사용한다.
- 노드 반지름은 `1.35 + sqrt(비율) × 1.65`로 제한한다. 보이는 노드는 작게 유지하되 투명 비스케일링 스트로크로 약 44px의 터치 영역을 확보한다.
- 기본 노드에는 우리 팀 등번호 또는 상대 선수의 짧은 식별자만 표시한다. 전체 이름은 선택 상태와 접근 가능한 이름에서 제공한다.
- `from → to` 데이터는 화살표로 표현한다. 반대 방향 연결이 함께 있으면 서로 다른 곡률로 분리한다.
- 선 굵기와 명도를 완료 횟수에 함께 매핑하고, 선택하지 않은 노드와 선에는 광원 효과를 사용하지 않는다.
- 공식 집계의 참조 포메이션을 실제 평균 위치처럼 표현하지 않는다. 상위 연결만 표시한다는 사실도 차트 위와 설명에 반복한다.

### 전술판

- 선택된 선수, 조작 가능한 속성, 변화된 지표 사이의 인과관계를 한 시야에서 확인해야 한다.
- 드래그, 방향키, 교체, 역할 변경 뒤에는 선택 상태와 수치가 즉시 갱신돼야 한다.

### 결과

- 점수 하나로 결론을 대신하지 않는다. 채택 판단, 변화량, 이점, 리스크, 운용 조건을 함께 제시한다.
- `경기 결과 예측이 아닌 코칭 검토` 문구를 결과 위계 안에서 계속 노출한다.

### 범용 스튜디오

- 처음부터 모든 기능을 설명하지 않는다. 템플릿 → 선수 배치 → 장면 → 분석·공유의 순서를 유지한다.
- 자동 저장과 내보내기의 성공·실패 상태는 `role="status"` 또는 `aria-live`로 전달한다.

## 7. 축구 시뮬레이션 전술 UX 적용

- [EA SPORTS FC 26 Gameplay Deep Dive](https://www.ea.com/en/games/ea-sports-fc/fc-26/news/pitch-notes-fc26-gameplay-deep-dive): 포메이션보다 역할과 포커스가 실제 움직임을 세분화하며, 전술 분석·저장·불러오기·비소유/소유 뷰를 한 흐름에 둔다.
- [EA SPORTS FC 25 FC IQ Deep Dive](https://www.ea.com/en/games/ea-sports-fc/fc-25/news/pitch-notes-fc-25-fc-iq-deep-dive): 포메이션, 수비 접근, 빌드업, 선수 역할, 전술 슬롯과 경기 중 교체를 분리해 조작한다.
- [Football Manager 26 전술 진화](https://www.footballmanager.com/fm26/features/possession-out-possession-fm26s-new-tactical-evolution): 볼 소유/비소유 형태와 역할을 시각화해 기본 대형과 실제 움직임이 다름을 설명한다.
- [IFAB 경기 규칙 3조](https://theifab.com/laws/latest/the-players/): 공식 대회 기준 최대 5명 교체와 최대 3번의 교체 기회를 상태 모델의 상한으로 사용한다.

적용 원칙은 다음과 같다.

1. 포메이션은 4백·3백·5백 계열로 분류한 16개 공용 카탈로그에서 선택하며 가이드와 범용 스튜디오가 같은 좌표 데이터를 사용한다.
2. 포메이션은 비소유 기본 위치로 설명하고, 역할·직접 배치·팀 지시가 볼 소유 시 움직임을 만든다는 관계를 노출한다.
3. 교체는 단일 완료 상태가 아니라 최대 5명의 순서 있는 계획으로 저장한다. 교체 아웃 선수의 재투입을 막고 직전 취소·전체 취소를 제공한다.
4. 팀 지시는 빠른 프리셋과 세부 슬라이더를 동시에 제공해 초보자와 숙련자 모두 같은 화면에서 시작할 수 있게 한다.
5. 범용 스튜디오의 배치 변경은 실행 취소와 다시 실행을 모두 제공한다. 결과 화면에는 최종 교체 계획을 의사결정 메모로 남긴다.

게임 화면, 상표, 아이콘, 문구는 복제하지 않는다. 조작 구조와 피드백 원칙만 RE:TACTIC의 데이터 기반 코칭 흐름으로 다시 구현한다.

## 8. 변경 완료 기준

1. 실제 경기 흐름과 범용 스튜디오의 핵심 조작이 모두 동작한다.
2. 키보드만으로 모드 선택, 단계 이동, 폼 편집, 선수 선택·이동, 결과 확인이 가능하다.
3. 320px 이상에서 가로 스크롤이 없고 390×844에서 주요 행동이 발견 가능하다.
4. 포커스 표시와 색상 대비가 다크 배경에서 분명하다.
5. 모션 감소 설정을 존중하고 애니메이션이 조작을 막지 않는다.
6. `npm run typecheck`, `npm run build`, Playwright 핵심 흐름을 통과한다.
