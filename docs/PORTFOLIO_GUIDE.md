# 데이터 분석 직무 관점의 읽기 가이드

이 저장소는 예측 대회와 분석 학습 기록입니다. 운영 데이터로 사업 효과를 검증한 사례는 포함하지 않습니다.

| 확인할 역량 | 추천 증거 | 면접에서 설명할 질문 |
|---|---|---|
| SQL로 데이터 탐색 | K리그 프로젝트 `sql/`, README의 EDA | 어떤 집계에서 가설을 얻었고 무엇으로 검증했는가? |
| 시간에 따른 데이터 변화 | 투구 README의 시즌 변화와 시간축 검증 | 무작위 분할 대신 연도 검증이 필요한 이유는? |
| 지표 해석·오차 분석 | 모기 README의 OOF/LB 비교, 식음업장 지표 분석 | 평균 점수가 좋아져도 제출 결과가 나빠지는 이유는? |
| 실험 설계·선택 근거 | 투구 `research/reports/`, 풍력 실패 기록 | 채택하지 않은 후보는 어떤 기준으로 기각했는가? |
| 재현·협업 | 투구 `final_submission/verification/`, 테스트 | 체크포인트 재조립과 신규 학습 검증은 어떻게 다른가? |
| 분석 결과 전달 | 각 README의 결과·한계, RE:TACTIC 프로토타입 | 관측 사실과 모델·휴리스틱의 추정을 어떻게 구분하는가? |

투구는 5인 팀 성과입니다. 작성자는 EDA, 특징 설계, 검증, 학습, 앙상블 및 재현 패키지의 전반을 담당했습니다. 이는 본인 설명에 따른 기여 범위이며 팀원 기여를 배제하거나 독점 기여율을 뜻하지 않습니다.

공개 데이터로 가능한 코드를 먼저 읽고, 비공개 자산이 필요한 경로는 각 README의 제한을 확인합니다. 수백 개 실험 파일은 연구 이력이며 모두 실행해야 하는 필수 단계가 아닙니다.
